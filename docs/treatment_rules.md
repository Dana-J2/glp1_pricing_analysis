# 치료 지속·중단·재개 v1.1 — 통합 전 수정본

## 확정한 계산 규칙
- 첫 조제일을 0일로 두고, 약제 보유기간은 [0, 28)일이다.
- 다음 조제 예정일(28, 56, …일)에 **중단 여부를 먼저 판단**한다.
- 지속자는 당일 조제하고, 중단자는 당일 조제하지 않는다. 기존 조제를 소급 삭제하지 않는다.
- 중단일 = 마지막 조제일 + 28일. 중단일을 d라고 하면 재개 가능일은 d+60일이다.
- 재개 창은 [d+60, d+150)으로 90일, 창 전체 재개확률은 25%이다.
- 재개일 첫 조제는 확정, 치료 시계 초기화. 외부 지급 이력은 그대로 유지한다.

## 중단 감소율
문헌 기준곡선을 S(t)라 할 때:

$$
q_t = 1 - S(t+1)/S(t).
$$

$$
q_t^* = (1-r) m q_t.
$$

r은 중단 감소율, m은 재개 후 중단확률 배수(첫 치료는 1)다. 일별 조정 확률을 누적한 생존곡선으로 조제 간격의 중단확률을 계산한다.

$$
Q_{a,a+28} = 1 - \prod_{t=a}^{a+27}(1-q_t^*).
$$

확률을 자동으로 1에 잘라 맞추지 않는다. 현재 구현은 0 이상 1 미만만 지원하고 범위를 벗어나면 오류를 반환한다.
기존 입력키 `postrestart_stop_hazard_multiplier`는 호환을 위해 남겼지만 **이제 일별 조건부 중단확률 배수**다. 입력 엑셀의 `restart_stop_mult`에 대응한다.

## 문헌곡선과 실제 상태 비중의 구분
- `reference_persistence`, `first_course_survival`: 연속적인 문헌 기준곡선/조정곡선이다.
- `on_treatment`: 당일 조제 판단 후 약제 보유 상태의 기대 비중이다.
- 조제 사이에는 이전 조제분이 남으므로 상태 비중은 계단형이다. 91·183·274·365일의 실제 상태 비중이 문헌 기준점과 정확히 같지는 않다.
- 기본값에서 28일 조제 경계의 최초 치료 지속률은 문헌 곡선과 일치한다. 경계 사이에는 직전 조제 경계의 값을 유지한다.
- 이는 28일분 규칙적 조제에 맞춘 연구용 시간 이산화이며 새로 관측한 임상 수치가 아니다.

## 기존 결과와의 관계
기존 코드도 재개 창을 마지막 조제분 종료일+60일로 설정했다. 따라서 기본값에서는 이번 수정으로 조제·재개 건수가 실질적으로 변하지 않는다. 수정 목적은 상태 정의와 사건 순서를 명확히 하는 것이다. 중단 감소율이나 재개 배수를 바꾸면 확률 조정 방식 변경으로 차이가 생길 수 있다.

## 통합 API
- `DailyTransitionKernel.initial_state(first_day, external_history)`로 시작 상태를 만든다.
- `advance(state, day)`는 당일 중단·조제·재개를 반영해 다음날 입력할 분기를 반환한다.
- 조제일의 상태 비중은 **advance 후** 합산한다.
- `dispensed_today=True` 분기에만 대기기간·지급횟수 등 보험금 규칙을 적용한다.
- `external_history`에 지급 횟수를 저장하고 통합 모형에서 갱신한다. 서로 다른 지급 이력을 합치지 않는다.
- 사망·해지는 모든 상태에 통합 모형에서 한 번 적용한다.
- `treatment_pathway()` 집계 결과에는 지급한도·사망·해지가 없다.

## 실행
프로젝트 폴더에서 Python 3.10 이상, NumPy를 사용한다.

```bash
python -m unittest discover -s tests -v
# 전체 조제 재현은 treatment_pathway() 호출 또는 tests를 사용
```

기존 params.json과 입력 CSV를 유지했다. 12개 테스트를 통과했다. 추가 테스트는 조제 전 중단 처리, 일별 확률 보정식, 재개 포함 상세 API와 집계 모형 일치, 분기확률·인원 합을 확인한다.

## 파일
