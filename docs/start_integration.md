# 2단계: 최초 치료 시작률의 계약 모형 연결

## 범위
해인 기준 일별 조건부 시작확률을 생존·유지·미시작 계약에 적용한다. 지급횟수·급부·보험료는 아직 없다.
치료 시작 후 집단은 현재 하나의 생존 집단으로 추적한다. 다음 단계에서 성환의 상세 치료 상태와 지급 이력으로 교체한다.

## 임시 기준
49세 여성, 최초 적격·미경험 가입자 1,000명, 2026-11-15 계약, 10년, 월 해지율 0, 사망력 배수 1.
49세 여성은 연결 검증용 후보이며 최종 가입자 설정이 아니다. 배수 1은 기초표 그대로라는 가정이지 비만 위험의 관측값이 아니다.
사망률은 기존 `outputs/input_v01/input_data.json`의 사망률 시트에서 가져왔다. 연령·성별·공표/보간 구분·출처를 data/reference/mortality.csv에 보존했다. 최신 원본과의 재검수는 이번 범위에 포함하지 않았다.
SELECT의 HR은 특약 가격에 넣지 않았다. 사망보험금 변화 분석과 구분한다.

## 일별 순서
전일까지의 생존자 → 월납일 직전 해지(가입 당일 제외) → 미시작 유지자에 일별 시작확률 적용 → 하루 동안의 사망 → 다음 날.
신규 시작자도 당일 하루의 사망에 노출된다. 연 사망확률을 365일 기준 사망력으로 환산한다. 보험나이는 계약 응당일에만 증가한다.

## 다음 단계 연결
`eligible_naive_before_start`가 시작률 분모, `new_starters`가 당일 치료 상태로 들어갈 인원이다.
새 시작자에게 성환 커널의 initial_state를 생성한다. 이번 코드의 started 집계는 상세 치료 상태로 대체하고, 모든 상태에 하루 사망을 한 번 적용한다.
이미 사망을 적용한 집계 결과를 다시 상태에 적용하지 않는다. 사망·해지가 없는 성환 집계 함수에 new_starters만 넣는 것으로 통합이 끝나지는 않는다.

## 파일
- start_integration.py: 입력검사·시작자 계산·요약 출력
- test_start_integration.py: 7개 검증
- config/rider.json: 임시 기준
- outputs/start_rate/start_probabilities.csv: 해인의 6개 시나리오, 이번 실행은 base
- data/reference/mortality.csv: 기존 기초 사망률
- results/: 사망 없음/있음 × 특약 없음/있음 결과

## 실행
```bash
python -m models.rider.start_integration
python -m unittest discover -s tests -v
```
저장소 루트에서 실행한다. 월납 해지 기능은 포함했지만 기본값은 0이며, 양의 해지율을 급부·수지에 쓰려면 해약환급금 규칙도 정해야 한다.
