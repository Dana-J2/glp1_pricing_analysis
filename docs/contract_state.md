# 3단계: 지급 횟수·계약 상태

## 추가한 내용
- `ContractState`: 계약 상태, 누적 지급 횟수, 성환의 치료 상태.
- 계약 상태: active / exhausted / matured / dead / lapsed.
- 미시작은 treatment=None, 이 집단에만 해인의 p_start_yes 적용.
- 지급 이력은 상태 키에 포함되어 서로 다른 지급 횟수가 합쳐지지 않는다.
- 조제일이 대기기간 종료일(90일) 이상이고 만기 전이면 지급 횟수 1 증가.
- 13회 지급하면 exhausted, 이후 시작·재개·조제·지급을 계산하지 않는다.
- 재개는 치료 시계만 초기화하고 지급 횟수는 유지.
- 당일 재개·지급 여부와 소진 이벤트를 반환하므로 다음 단계의 반환·납입 계산에 연결 가능.

## 통합 순서
1. 날짜별 만기 확인(만기일 급부 없음).
2. 월납일 직전 해지 및 보험료 수입 처리(수입은 다음 단계).
3. `step_population()`에 오늘 시작확률·성환 커널·지급 규칙 전달.
4. `paid_claims` 이벤트에 정액을 곱해 급부 계산(다음 단계).
5. 소진 당일 미경과보험료 반환(다음 단계).
6. `apply_exit()`로 남은 active 상태에 하루 사망 반영.

종료한 특약의 상태는 회계용 종료 집계이다. exhausted/matured 집단의 이후 생존·치료 경로는 이 모듈에서 추적하지 않으며, 기존 사망보장 영향은 별도 모형에서 추적해야 한다.

## 검증
중단 없이 가입 당일 시작하는 시험 경로: 0·28·56·84일 조제는 대기기간으로 미지급, 112일부터 448일까지 13회 지급, 이후 지급 없음.
그 밖에 대기 종료일, 만기일, 재개 시 지급횟수 유지, 다른 지급 이력의 분리, 확률질량 보존, 종료 계약의 무지급을 확인했다.
기존 19개 + 신규 7개 = 26개 테스트 통과.

## 현재 한계
상태전이 구성요소와 작은 검증 경로까지 완료. 전체 10년 상세 상태 전이의 실행시간·집계, 금액 급부·월납·반환·사업비·보험료는 아직 계산하지 않았다.
